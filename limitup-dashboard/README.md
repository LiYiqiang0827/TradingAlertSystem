# TradingAlert 涨停研究台

与 `offlineAlertSystem/` 同级的本地 HTML 原型，默认只读访问 Mac mini 上 TradingDataManager / TradingDataBase 的现有数据。

## 主导航（导航改版后）

- 左侧保留交易状态、日期时钟、实时数据开关，以及启用实时数据后的“实时监控”入口。
- 常驻入口依次为“涨停天梯”“每日总览”“重要指数”。重要指数直接进入指数总览，不再展开指数子列表。
- 题材和个股导航使用涨停天梯；左侧不再提供旧的题材/板数列表、日历、搜索、排列方式切换和全局加号。各页面内的日历保留。
- 改版前基线标签：`ladder-pre-nav-redesign-v1`，固定在 `2ec366f`；后续导航调整不移动该标签。

## 新机安装与启动

依赖仓库：[TradeDataManager](https://github.com/LiYiqiang0827/TradeDataManager)，配套版本为两个仓库的 `theme-graph-chain-v1` 标签。[完整配置、结构、生成/入库与两天最小示例](https://github.com/LiYiqiang0827/TradeDataManager/blob/theme-graph-chain-v1/theme_graph/PORTABLE_SETUP.md)。核心类的确切路径为 `coreClient/neo4j_client.py`，随 `pip install -e '.[graph]'` 安装，Neo4j driver 不是网页仓库内置依赖。

```bash
export TRADING_DATA_MANAGER_ROOT="$HOME/TradingDataManager"
export TRADING_DATABASE_ROOT="$HOME/TradingDataBase"
# 按 manager 的 theme_graph/.env.example 配置自己的 Neo4j URI/密码。
cd ~/TradingAlertSystem/limitup-dashboard
"$TRADING_DATA_MANAGER_ROOT/.venv/bin/python" server.py
```

Python >=3.10；默认监听 `127.0.0.1:8765`，可用 `TRADINGALERT_HOST/PORT` 修改。源码和数据库路径均可配置，不依赖某位用户的 home。`.env` 需手动 source；不会自动加载。Neo4j 本身需单独启动，只有 Python driver 不够。Redis 可选。示例与正式数据应使用不同的目录、Neo4j 实例和端口。

## 数据与缓存

- 题材摘要、个股涨停原因：从 Neo4j `HAS_DAILY_SNAPSHOT` / `ATTRIBUTES_LIMITUP` 读取，原始日报保存在 `$TRADING_DATABASE_ROOT/theme_graph/每日涨停原因/YYYYMMDD.md`，网页不直接解析原始日报。
- 涨停池：优先 `tbl_cn_kpl_list`，当日没有数据则使用 `tbl_cn_kpl_limit_performance`
- 日线预载 2 年、周线预载 5 年、月线载入当前数据库中的全部历史，1 分钟预载最近 5 个交易日，15 分钟载入最近 3 个月
- 每个周期独立缓存到 Redis DB 2，键按股票、周期、截止日期区分，复盘日数据缓存 7 天，最新行情缓存 5 分钟；缓存命中后不重复读取 data provider
- 选中个股时同时预载复盘日与数据库最新行情并写入 Redis，图表一次载入两段数据；“最新K线”按钮只滚动显示范围，不请求接口、不重取数据；最新行情缓存 5 分钟
- 1 分钟图只使用 1 分钟表，15 分钟图只使用 15 分钟表；15 分钟表覆盖不足时显示实际覆盖区间，不用 1 分钟数据拼接替代
- 浏览器使用有容量、字节和到期限制的 LRU 内存缓存及 IndexedDB 持久缓存。历史数据按股票和复盘日期保存 7 天，完整个股页、悬浮图预览、日线预加载使用独立键；数据版本变化后正常读取不会复用旧版本。
- 服务端优先使用本机 Redis `127.0.0.1:6379/2`；Redis 不可用时仍回退到项目内 SQLite 持久缓存 `cache/dashboard-cache.sqlite3`
- Redis 服务不可用时原型仍可启动。Redis 不会由本项目自动安装或启动

## 涨停天梯预载与缓存

- 首次打开、通过日历切换截止日：读取并绘制截至该日的最近 20 个有行情数据的交易日；不足 20 日时使用全部可用日期。
- 日期滑条和左右键优先复用已载入的原始数据，只在鼠标释放后重新计算截止日可见的题材、节点和连线；不展示截止日之后的节点，也不使用未来节点决定题材归类。
- 画布接近已载入范围左侧时，提前补载下一批 20 日（与上一批重叠 1 日以衔接晋级路径）；拖动中完成的补载延至释放鼠标后绘制，保留当前视野。
- 服务端 Redis 键使用 `limitup-ladder:v14:截止日:交易日数:数据库版本`。历史窗口缓存 24 小时，当日窗口缓存 5 分钟。
- 浏览器内存和 IndexedDB 各保留最多 24 份数据块；刷新页面后可恢复 IndexedDB 缓存，同一版本的并发请求合并。
- `/api/ladder-version` 依据 KPL、日线数据库及非空 WAL 的大小和修改时间生成版本。浏览器最多每 30 秒校验一次版本；源库更新或历史修复后旧数据块不再复用。
- 题材颜色在当前页面会话内持续保留，拖动或日历切换不会给已有题材重新排色。
- 首次计算通过候选交易日的索引存在性查询、近期涨停前驱索引和按需历史锚点查询，避免全表日期去重和逐股远期回溯；日线在内存中统一排序，保持停牌、跨日形态及晋级链的原有口径。

## 天梯展开状态与图例导航

- 首次打开时，所有板数的未晋级列表、首板和破板的“其他题材”统一默认收缩，工具栏显示“展开”；三板及以上题材内的未晋级股票也使用折叠列表。
- 工具栏“展开/收缩”统一控制这些列表；双击三板及以上的未晋级控件只控制三板、四板和高板，二板仍单独控制。
- 图例默认勾选“指定日”，并按题材最高板收缩归类；圆圈显示该题材当日全部涨停数，大小随数量变化。高板旁的“展开/收缩”可切换为各板分别列出。
- 图例指定日超出画布当前可见日期范围时，同步调整画布截止日和右侧日历；范围内只改变图例。
- 图例悬浮框左上角题材名单击进入题材页面：指定日模式使用该日，区间模式使用区间末日；页面保留返回涨停天梯的入口。
- 主画布题材名单击聚焦并压缩题材；股票名单击仅按股票代码高亮跨日期标签及连线，其他股票淡出，不改变几何布局或滚动位置。再次单击同股、Esc 或“全”恢复；双击仍进入对应页面，返回天梯保留聚焦。悬浮框中的链接保留单击跳转。

## 紧凑天梯的再次首板连线

- 仅题材聚焦/板数筛选后的紧凑版面显示新增虚线；回溯 10 个交易日内同股票最近一次已确认的断板或首板破板，不连接正常连板、几天几板续连或纯停牌后直接晋级的路径。
- 新增边单独缓存和绘制，不参与晋级率、板数或晋级链题材合并。符合条件的再次首板，股票板数框改为正方形并保留一字、T 字、强弱板的描边规则。
- 出口已有“停”圈或红叉时复用原标记，仅没有这些出口时补“续”圈；多股标签的虚线进入该股票行左侧内部窄槽的专属“续”圈，单股标签复用原计数圈；原计数圈始终贴住矩形外缘。入口圆圈显示上一次涨停状态（破、板数或板数/天数），右侧显示断开日期与交易日间隔，出口小字保留再次涨停日期与间隔。
- 间隔按交易日历从实际断板/破板日算至再次涨停日；缺失日线不视为已确认断板，所有候选日期不超过所选截止日。

## 未晋级归类与续接入口

- 每条未晋级记录只归属一次：按昨日板数加一的冲击档位分组，五板及以上合并到高板，不再同时复制到首板汇总。题材卡内部有对应档位时放卡内，否则放该档的未晋级汇总；前板数缺失的记录才使用首板兜底。
- 股票聚焦期间隐藏未晋级标题及数量入口，保留布局和该股票自身的历史记录；取消聚焦后恢复。
- 断板续连、停牌续接和再次首板采用相同的细虚线样式；聚焦股票后，相关路径使用一致的高亮样式。
- 单股题材标签复用原左侧计数圈作为续接入口。多股标签保留贴住矩形外缘的计数圈，另在左侧内部窄槽按股票行设置“续”圈，两种圈都与矩形边缘相接。

## 天梯题材悬浮名单

- 悬停图中题材名称，显示标签当日、当前统一题材归属下的完整涨停名单，固定按高板（5 板及以上）、四板、三板、二板、首板分组；空组显示横线。N 天 M 板按 M 板分组，圈内保留 M/N。
- 列表包含板数圈、股票名称、当日涨幅、首次涨停时间、封板金额和简略原因；一字/T 字红色实线圈、强板红色虚线圈、弱板题材色虚线圈。创业板与科创板股票名在表格和天梯中均为红色。
- 封板金额与涨幅按日期从本地行情表批量读取；简略原因复用 Neo4j 当日归因，优先对应题材，兼容旧日报题材标题后按股票代码匹配，缺失显示横线。
- 补充字段通过 `/api/ladder-topic-details` 延迟加载，不增加 20 日初始数据体积；服务端 Redis 和浏览器内存缓存 5 分钟，同日请求复用。列表可独立滚动，点击股票可进入个股页，移开鼠标或 Esc 关闭。

- 每日行情、个股和指数请求均校验请求序号与当前路由。切日期、切页面后迟到的响应及错误不会覆盖当前页面；日期加载的调用方同样停止过期导航，返回日期异常时显示读取失败。

- 天梯绘图预先按日期、板数、题材建立索引，续接入口使用集合查找，保留排序与路径口径。直接进入天梯、题材或指数时跳过临时每日总览的绘制和附带请求。JSON 大响应在浏览器支持时使用 gzip，尊重禁用 gzip 的请求。

### 多日续连节点与可见性

- “几天几板”晋级的前驱以 KPL 涨停表现、KPL 涨停名单、涨停列表里可核实的节点为准；不让仅日线存在、三套涨停源均无记录的隐形节点截断可见链条。日线仍用于封板校验和连续板计算，不修改行情表。

- “几天几板”的断板续连也使用逐股“续”入口及日期/交易日数标注；断板出口按股票行分别显示“断”，不合并。单股卡复用原入口大圆承接续连，保留数量/晋级比例并使用题材色描边和文字，不额外增加圆圈；停牌跨日晋级也逐股显示“停→续”，日期/交易日数小字附股票名；正常连续晋级仍使用原来的合并出口。

### 天梯工具栏搜索

- 工具栏左上角放大镜打开搜索框，按当前已加载且不晚于截止日的天梯数据匹配股票名或题材名，也可输入股票代码；不额外请求历史数据库。
- 题材结果复用题材单击的聚焦/压缩操作；股票结果复用左侧图例股票单击的单股紧凑脉络操作，可从已有筛选中切换到目标；较早日期的匹配项会滚入视野。

### 每日总览与日期悬浮概况

- 每日总览左上角始终显示“← 返回涨停天梯”。总览日期在原天梯可见区间内时恢复原视图；超出时以总览日期为天梯截止日。
- 总览的“指数”标题打开重要指数页，各指数卡片打开对应指数详情。
- 天梯日期悬浮窗在题材表上方显示当日 8 个核心指数的点位、涨幅和成交额，以及题材数、涨停数、最高板与所属题材、涨停股最多的题材、总体晋级率和破板率。
- 晋级率 = 昨日全部涨停股中今日再次涨停数 / 昨日全部涨停数；破板率 = 当日触板未封住数 / 当日全部触板数，包含冲击连板失败。行情取自对应交易日离线数据；缺失项显示横线。日期补充接口按数据版本缓存，新增概况只查询今日与前一交易日，不执行 60 日全量市场复盘。

### 指数名称悬浮行情与来源导航

- 天梯日期悬浮窗和重要指数页的指数名称支持悬停，显示基本行情、5 日分时、日 K、15 分钟图，截止日使用来源日期。
- 名称单击进入对应指数页，复用指数内存、IndexedDB 与服务端缓存；从上述历史截面进入时默认截止来源日期，可在设置中手动切换最新日期。
- 从天梯进入指数详情，左上角显示“← 返回涨停天梯”，保留来源视图。总览也使用相同文字；返回日期在原可见范围内时恢复原视图，只有超出范围才调整天梯截止日。

### 天梯表格自由换手率

题材悬浮表、日期悬浮表及其嵌套题材表在涨幅后显示“自由换手率”，取同一交易日 `tbl_cn_daily_basic.turnover_rate_f`，保留两位小数及百分号，缺失显示横线。数据按日期批量读取并随补充详情接口缓存，覆盖涨停、未晋级和破板股，不逐股请求基本信息。

### 盘中实时天梯

- 交易中或午休且 Redis 存在当天新鲜涨停/题材快照时，天梯最新日期增加当天；指定的历史截止日仍保持历史视图。当前日期的股票名右侧显示当前涨幅，涨红跌绿。涨幅显示覆盖涨停以及展开的未晋级、破板股票。
- 页面以 SSE 接收采集完成事件；观察股快照、指数快照和 KPL performance 均以 3 秒开始到开始为目标（源接口耗时超限时顺延），涨停池约 30 秒、破板池约 60 秒。工具栏显示快照时间，关闭“实时数据”开关即暂停推送。
- 服务端以最新可用报价与当天官方涨停价格核对，题材优先采用实时 KPL performance，复用历史天梯的多日多板、断板续连和停牌连接算法。未拿到新鲜报价的股票保留待确认状态，不直接判未晋级；盘中路径出口为待确认，收盘前均属临时状态。
- 当日全量替换，避免开板后残留旧涨停节点。实时返回绕过历史 IndexedDB 缓存，服务端按快照版本短缓存 10 秒。数据过期/中断显示待更新并保留上一快照；当前视图收盘后保留最后显示快照，新开页面仍由已入库的离线日期驱动。
- 本功能增加的是天梯实时状态；独立归因、离线自由换手率及完整分钟历史仍遵循各自的数据更新链路，缺失不以昨日值冒充今日数据。

### 当天悬浮行情补充

实时日期悬浮窗的指数概览取当天 Redis 指数快照，按 10 秒短缓存更新。当天个股悬浮图绕过历史浏览器缓存，从 TDX 读取原生 1 分钟和原生 15 分钟数据，接到离线历史上；当天日 K 使用最新报价及分钟行情更新，服务端短缓存 6 秒。未完成的原生 15 分钟 K 使用周期结束时间标记。历史日期继续保持原来的截止日，不引入之后的数据。

当前交易日的个股和指数悬浮窗保持打开时，由对应的数据更新事件触发三周期行情补充，更新原图和基本信息；关闭悬浮窗、关闭实时开关或页面在后台时暂停读取。失败保留最后一份行情，下一事件重试。浏览历史日不轮询。分时横轴补齐到当天 15:00，跳过午休；未来时间槽仅有时间戳，不绘制价格、均价或成交量。

### 首板卡片完整成员与实时展开

- 首板保留原有题材筛选：截止日保留有连板的题材及首板数量前三的题材，更早日期保留有首板晋级的题材。保留的题材卡片列出该题材当天全部首板股票，不再只绘制一只代表股或只有晋级的股票。聚焦题材时也补全选中题材各日的首板成员，板数仍按几天几板中的板数分组。
- 实时当天的未晋级与其他题材（含破板区聚合卡）默认展开，历史日期默认收起。默认值只初始化一次；手动折叠后刷新不会重新展开，批量收缩也约束随后新增的实时分组。

### 首板次日结果分区与历史涨幅

首板卡片把已知次日未晋级的股票放到下段，与晋级/待确认部分用横线分隔，下段共用一个红叉。判断采用同股下一交易日的实际涨停和未晋级记录，超出当前截止日或缺少次日行情时不判失败，停牌不凭连线缺失判失败。原有断板、停牌续接及股票定位保留。未晋级列表和首板卡片的未晋级段按标签当日涨幅降序排列，缺失置后。所有历史/实时股票名后显示标签当日涨幅；涨红跌绿，历史涨停股涨幅优先取同日 KPL performance 的 pct_chg，再依次取 KPL list、tbl_cn_limit_list、日线；空串、非数值和非有限值跳过，节点 pctSource 记录来源。未晋级等不在涨停池的记录继续用当日日线补缺，历史数据不借用最新报价。天梯接口 schema 升至 15，历史与实时服务端缓存及浏览器缓存随之换版。

### 主动行情推送与午间快照

实时行情使用 `/api/live-events`（SSE）：服务端以一个共享 `XREAD BLOCK` 读取 TradingDataManager 提交的 `online:events`，向浏览器推送发生变化的报价及批次版本。页面只有一条长连接；交易状态来自 15 秒心跳，1 秒本地时钟不请求行情。首次进入、切换数据范围或断线重连时读取完整快照；收到新事件后按需补充图表数据，移除了实时页 10 秒、天梯和悬浮窗 15 秒定时请求。只有报价变化时更新涨幅文字，题材/板数/涨停状态或未晋级排列顺序改变时才重算天梯。原生 1 分钟和 15 分钟图仍使用原生数据。

页面隐藏或实时开关关闭时关闭连接，恢复后重连并补齐。SSE 自动重连，断开期间保留旧图。每个客户端队列有界，积压时要求重新同步。服务状态可通过 `/api/live-push-status` 读取。

配套生产者位于 TradingDataManager 的 OnlineRedis.emit_update 及六个 writer。个股、指数与 KPL performance 配置为 3 秒开始到开始的目标周期，五个板数请求并行；网络耗时超限时不重叠采集，错误退避。事件成功提交后才使实时缓存失效。新部署需要两仓库同步，并优雅重启 online scheduler 和网页服务。

午休仍提供当天的天梯日期，标为“午间快照”；读取同日最后完整批次，短 archive 过期则从源业务 Stream 恢复，下午新行情到达后继续推送。历史日期不改用实时数据。

实时图例更新保留现有节点：当日成员直接复用天梯完整响应，不先清空图例再加载。只有涨幅变化时就地更新文字，封板金额等补充数据仅在股票列表展开时按采集事件补充；相同图例内容跳过 DOM 更新，成员变化时按题材和股票标识增量更新，保留列表展开状态及滚动位置。

实时天梯以题材标签、股票和连线的稳定标识增量更新 SVG，保持既有线条和节点；行情更新复用历史卡片缓存，连线不使用透明度过渡。未晋级仍保留在原晋级档位，当日曾触及涨停的个股圈内显示“破”，未触及涨停显示“未”，此规则共用于天梯、图例、悬浮表格和个股页。

悬浮窗的五日分时采用图中首个交易日的昨收作为累计涨幅 0%，左轴价格、右轴累计涨幅，正负范围对称；黄色虚线标记该 0% 基准和所选日期昨收。日 K 价格区光标图例显示额、幅和自由换手率“换”，底部成交量指标不变；chartSeriesVersion=6 使旧缓存重新读取。左侧时钟按服务器校准的北京时间逐秒显示；天梯“行情更新”标记批次时间和距今秒数，悬停查看最近收到推送的时间。

闭市后当日离线涨停行情尚未就绪时，天梯保留同日 online 收盘快照；不受实时开关关闭影响，首次打开、刷新、日历均可进入。Redis archive 过期时读取源 Stream，Stream 不可用时读取 online/online_data_YYYYMM.db 的当日最后批次（指数和个股报价按代码保留最新值）。不以昨日数据冒充今日。界面标为收盘快照，缺少独立归因仍显示没有数据。离线就绪条件为当日涨停池存在，且日线/涨跌停价覆盖当日池及昨日涨停群体，已知全天停牌除外；不等待 Neo4j 或次日 KPL list。SSE 心跳携带就绪状态，切换时保留历史窗口、筛选和选股状态。

分时图光标“幅”按光标所在交易日的昨收计算当日涨幅；右侧坐标仍按五日首个交易日昨收计算累计涨幅，二者口径各自固定。


### 当日悬浮窗的估算基本面和封板资金

`/api/live-stock-chart` 与当日 `/api/stock-facts` 共用实时基本信息。已有当日 `tbl_cn_daily_basic` 时优先使用正式值；缺失时，用上一交易日的流通股本乘今日价格估算流通市值，用今日累计成交股数除以上一交易日自由流通股数估算自由换手率（百分数）。股本单位为万股，online snapshot 成交量单位为股；不直接复制昨日换手率。缺少 `free_share` 时可由昨日成交量与昨日自由换手率还原分母；无可靠分母则保留缺失。估算项标记“估”，悬停说明基准日期。

当前仍封住涨停的个股悬浮窗显示“实时封板资金”，来自当日开盘啦 performance / 涨停池中较新的非空封单金额；零值保留，开板后隐藏，不显示历史最大封单。当日原生分钟图保持短缓存，基本信息在响应时独立读取当前快照，沿用 SSE 更新已打开悬浮窗。闭市后对应数值是带行情时间的收盘快照。


### 分时光标换手与个股聚焦

个股悬浮窗五日分时光标增加“换”：每日从开盘累计至光标分钟的成交额（元）÷该交易日自由流通市值（元）×100%。自由流通市值使用同日 `tbl_cn_daily_basic.free_share * close * 10000`，当日尚未发布时复用昨日分母；不用 `circ_mv` 替代自由流通市值。每个交易日重新累计，悬停移动只查预先计算的时间戳索引。日线/分钟价格复权不会改变成交额或原始市值分母。此成交额口径为换手估计，不替代基本信息区的成交股数口径。

右侧单击股票名先按所属题材收缩行，再突出该股票线路；其余题材隐藏，同题材其他股票淡化。选中标签保留原填色和描边色，强调使用字重、线宽与不透明度。单击等待与题材名字一致的双击判定时间，双击仍进入个股页面。


### 晋级题材内的未晋级预览

二板及以上、同时有晋级股和未晋级股的题材卡，把可点击的未晋级数量圈与“未晋级”放在题材名一列。收起时右侧保留第一只未晋级股的一行预览（沿用涨幅排序），展开时显示全部；左侧标题按右侧名单高度垂直居中。一只股票在两种状态下均只占一行。列表高度、卡片高度和连接点沿用同一布局计算，首板和独立的未晋级题材汇总卡不受影响。


### 图表缓存与重复悬浮（2026-10-26）

读取顺序为浏览器内存 → IndexedDB → 服务端完整响应 LRU → Redis 中的基础序列 → 数据库或原生分钟源。同一请求在前端及服务端均合并，持久缓存写入异步完成，不阻塞画图。

| 层级 | 保留与淘汰 |
| --- | --- |
| 历史个股内存 | 按股票代码＋复盘日期分别存；最多 80 份 / 估算 64 MiB；绝对 2 小时、空闲 30 分钟，LRU＋定时过期清理 |
| 个股 IndexedDB | 新库 `tradingalert-market-charts-v2`，最多 200 份 / 估算 192 MiB；历史保留 7 天，当日交易中快照保留 2 分钟、闭市快照保留 6 小时，日期不会互相覆盖；按标量索引淘汰，不扫描或复制全部图表正文 |
| 基本信息内存 | 最多 200 份 / 估算 2 MiB，30 分钟；持久化结果随数据版本失效 |
| 当日快照内存 | 最多 40 份 / 估算 24 MiB；交易中最多复用 2 分钟的最近快照用于立即显示，随后刷新；闭市最长 15 分钟；SSE 强制更新绕过软缓存 |
| 指数缓存 | 内存最多 40 份 / 估算 32 MiB，持久缓存延长到 7 天；数据版本变化立即失效，不等待磁盘写入再显示 |
| 已绘制悬浮图 | 个股、指数共享，最多 3 组 / 32 MiB canvas 像素估算；空闲 5 分钟销毁；复用时恢复 K 线间距并定位所选日的最后数据 |
| 服务端完整个股响应 | 进程内最多 64 份 / 估算 64 MiB，30 分钟；数据版本参与键；空日线或读取失败的分钟结果不进入此缓存 |

`/api/stock-version` 返回独立的图表与基本信息版本，涵盖日线/复权、SQLite WAL、1 分钟 catalog/DuckDB WAL、15 分钟 DuckDB/WAL。浏览器合并版本请求，最多复用 60 秒；图表与基本信息补数后重读，而非简单依靠长 TTL。图表状态、个股页面、题材大图和悬浮窗共用股票历史请求缓存。

当日缓存采用先呈现最近快照、再更新现有 canvas 的策略；行情更新时间仍保留真实源时间。交易中原生分钟缓存为 3 秒，午休 60 秒，稳定收盘后 30 分钟（15:05 前仍为短缓存）；基本信息和封板资金在每次响应时独立读取最新快照。闭市不再额外请求并丢弃已过 60 秒的盘中报价。

诊断：悬浮窗 DOM 的 `data-cache-source`、`data-load-ms`、`data-render-ms`、`data-chart-reused` 可分别核对读取来源、等待、建图和实例复用；`X-Chart-Cache` 标记服务端完整响应的进程缓存命中。内存和磁盘容量均为预算估算，不代表浏览器/Python 全进程 RSS。升级后的旧版本浏览器记录不参与新版本读取。

数据版本变更不会立刻删除上次成功的图表。普通命中必须版本一致；只有遇到明确的数据库写锁、超时等暂时读取故障，才回退到尚未过期的同代码同日期快照，并显示“数据更新中，暂用最近缓存”。回退内容不会冒充新版本写入持久缓存，下一次读取或推送继续尝试更新。

题材分时/日 K 缩略图另设 30 分钟 LRU，分别最多 32 组 / 12 MiB 与 32 组 / 4 MiB；服务端缓存键同样包含行情版本。两市成交额、指数概览、涨停跨度也加入对应源版本，补数后不继续命中旧结果。股票完整响应版本同时覆盖涨停基础表，防止旧的板数跨度字段随图表长缓存残留。

本机浏览器现场读数（2026-10-26，计算与数据等待，不含鼠标悬停判定及屏幕刷新）：福莱新材 20261026 一次回源读取 1567.9 ms，再次内存读取 5.3 ms、图表复用 4.0 ms；页面刷新后 IndexedDB 读取 57.7 ms。大业股份在 20261022 与 20261023 间切换后，重看 20261022 命中内存 5.9 ms、图表复用 3.4 ms，截止日保持 20261022；上证指数重复悬浮读取 9.3 ms、图表复用 4.9 ms。盘中数据的新鲜度仍由来源批次和 SSE 决定，这些闭市读数不代表盘中链路延迟。


## 首次行情读取与日线预加载

- 网页读取每日行情后，空闲时后台预加载当日池内最多 24 只股票的日线（优先高板），每批 4 只，服务端并发上限 2；日线包含截至所选日期的最近 2 年。切换日期取消旧预加载，页面不可见时暂停，不阻塞导航。
- 日线记录同时存入浏览器内存/IndexedDB。悬浮时可以先显示已有日线，再补上原生 1 分钟和 15 分钟行情；历史悬浮使用 `/api/stock-preview`，不再加载完整个股页的额外 latest/周/月数据。完整个股页仍保留全部周期及最新行情。
- Redis DB 2 的 `stock-daily-basis:v1:<code>` 保存完整日线复权基础、复权因子和周/月聚合，TTL 7 天、最多保留 120 只；仅依赖日线所在 basic 数据库版本，不被分钟文件或 KPL 数据变化连带清空。进程内另有 64 项/32 MiB 的短期 LRU。
- 首次建立全量周/月线。源数据变化后对比全部日线，复用未变化周期，仅替换新增、修订、删除日线影响的周/月周期；这样同日多次更新不会把成交量重复累加。复权基准变化会校正所有受影响周期，历史修订也会被识别。源读取仍对照完整历史以检测修订，不宣称全链路只读新增行。
- `stock-daily-hot:v1` 记录最近访问股票，最多 120 只。服务启动及 daily/basic/复权等更新导致 basic 数据库版本稳定后，后台约 20–40 秒内启动刷新最近 48 只股票的 Redis 日/周/月基础。两个版本检查间隔 20 秒，持续写入时延后，避免反复重算。无需保持浏览器打开。
- `/api/stock-daily-preload?date=YYYYMMDD&codes=...` 每批最多 6 只；`/api/chart-cache-status` 返回缓存后端及后台刷新状态，不包含凭据。
- 在线单股基本信息优先对原始 Redis 批次执行 HGET；原始批次已过期时共享 Redis/进程内的最后有效批次，盘中 3 秒、休盘 60 秒、闭市 30 分钟，并按源批次及持久数据版本失效。
- 原生分钟下载连接最多并行 3 个，可复用 45 秒内空闲连接。闭市后每种周期独立检查离线覆盖：完整 240 根 1 分钟或 16 根 15 分钟且时间集合吻合时复用，否则仍下载该原生周期。不会以 15 分钟替代 1 分钟。
- 配套 TradingDataManager `e426e10` 的 `offlineDataManager/scripts/core/one_min_store.py` 将日期范围裁剪到实际 Parquet 文件列表，再传给 DuckDB；返回 datetime 统一为微秒类型。

- 指数的离线周/月表也在每日更新中按 period source hash 复用未变周期，仅对变动周期重算 OHLCV 和当期前缀；仍扫描源日线以识别历史修订，已落库周期的实时覆盖方式保持不变。


## 交互与并发性能维护（2026-10-26）

- 缓存加载使用按完整 key 隔离、引用计数回收的 `cache_singleflight.KeyedLocks`；允许同 key 重入，不同 key 不再因哈希桶碰撞互相阻塞。整页 → 周期、实时 → 历史的嵌套加载不会产生分桶锁的反向依赖。
- 每日行情统计（60 日板数历史、晋级率、破板等）独立存入 Redis `market-stats:v2:<date>:<membership-hash>`，记录源 basic/KPL 版本；版本未变即复用，变更时覆盖旧记录。TTL 7 天，最多 128 份，归因文字仍按原有短缓存更新。返回前复制，避免组装总览时 pop/补字段污染缓存。
- 确认离线已就绪后按 basic/KPL 版本缓存 24 小时；数据修订生成新版本，即时重新判断。未就绪仍短暂缓存。
- 初次进入涨停天梯时，并行读取天梯和总览；天梯先显示，总览只在背景补导航信息与日线预载。源数据首次冷读或版本变化仍可能触发合法重算，不承诺固定的首屏时间。
- API 请求设 30 秒期限，并保留调用者的取消信号。用户在天梯尚未加载完时进入其他页面，旧任务不会再向已移除的天梯 DOM 绑定事件。
- 同题材内高亮/取消高亮使用样式更新，保留标签和续接线路布局。严格单股模式仍只保留该股；题材模式的其他股票与线路变灰。DOM 的无 key 子节点匹配使用分类型队列，避免二次扫描；同一可见日期范围滚动时复用已应用的配色。
- 题材日历只按 KPL performance 的单一题材及涨停事实取日期，不再依赖 Neo4j 或旧 lu_desc 分类；无题材记录归入“暂无题材”，历史非交易日禁用。缓存按行情版本失效，浏览器短期刷新，不因归因缺失禁用当日。
- 诊断时可在首次加载 URL 加 `profile=1`，通过根元素 `data-api-profile` 查看最近 24 个请求阶段；不会在页面上显示诊断文字。`data-first-ladder-ms` 从 app 初始化计到首个天梯窗口数据就绪，不含脚本下载。

- 总览组装为完整破板列表显式补齐涨停跨度，避免首次计算依赖对象别名、Redis JSON 读回后字段丢失；统计缓存正文保持不变。


## 批量跨度与首屏合并（2026-10-26）

- 总览先收集当日所有需要展示跨度的股票，交易日历只读一次；涨停列表、KPL list、performance 的历史按每批最多 300 只读取。单股接口复用同一算法。Redis 使用 MGET / pipeline，SQLite 缓存降级路径也支持批量读取和写入，源版本和原跨度口径保持一致。
- 实际数据对比覆盖 20260401、20260901、20261008、20261023、20261026，共 580 个股票/日期组合，结果与改动前逐股算法一致。关闭跨度缓存后的批量计算为 41–69 ms，原实现为 742–1257 ms；其他缓存保留、仅跨度未命中时的 20261026 总览为 50 ms，原实现为 1170 ms。这些数值不代表所有数据首次冷读的整页时间。
- 初次绘图时合并快速到达的破板补充数据，最多等待 40 ms；补充数据冷读较慢时仍先显示天梯，稍后补全。热缓存现场同一源版本、同一日期由两次 SVG 构建减少为一次，观察到 app 初始化至天梯就绪约 429 ms → 304–317 ms（不含脚本下载）。
- 每次局部 DOM 更新后恢复日期滑条的 role、tabindex、ARIA 日期，旧监听器通过 AbortController 清除后重新绑定，避免展开/收缩后无法用键盘操作、或多次重绘积累监听器。
- 加载请求延迟失败时先核对当前页面与 DOM，离开天梯后不会操作空节点，也不继续为旧页面重试破板请求。拖动意外丢失指针捕获时恢复日期预览、处理待绘制数据并清理预取定时器。


## 实时推送批量失效与连接回收（2026-10-26）

- SSE 的行情和更新通知先按股票合并，再通过 `DeadlineLRU.setMany` 一次写入失效标记；每批只做一次过期检查、容量淘汰和定时器调度。单项 set 的 TTL、空闲期限和字节预算语义保持一致。
- 实时失效标记容量从 1024 提高到 8192 项 / 2 MiB 数值预算，保留 2 小时，避免全市场一批更新尚未处理完就淘汰前面的股票。推送报价只保存当前交易日，并设 16384 项上限；跨日清理，旧日迟到事件不覆盖新日状态。
- 5500 股票、同批包含 quotes 与 snapshot codes 的合成回放：浏览器原实现调度 11000 次清理计时器，耗时 140–210 ms，仅剩 1024 个标记；新实现调度 1 次，约 2.6–3.2 ms，保留 5500 个标记。Node 回放为约 1237 ms → 5 ms；不同运行环境的绝对数值不可混用。这不是盘中源头到浏览器的端到端延迟测量。
- `profile=1` 初次打开时，可在根节点的 `data-live-dirty-ms`、`data-live-dirty-batch`、`data-live-dirty-size` 查看实际推送批次的失效处理时间、去重股票数和标记容量。页面不显示诊断文字。
- 31 处只读 SQLite 作用域使用 closing 显式关闭，行情统计异常路径通过 finally 关闭连接；长期存在的 SQLite 缓存连接保留。禁用 GC 的隔离检查中，100 次交易状态查询的文件描述符增长由 201 降至 0；这是验证连接不再依赖垃圾回收，不代表原服务会永久保留所有连接。
- 查询计划已确认使用既有索引；日线查询的冷热对照没有形成可归因的查询改进，本次保留原查询与聚合方式。

## 所选日期与最新行情共用分钟读取（2026-10-27）

`/api/stock` 的所选日期和最新日期按分钟周期合并读取，再在内存中切分。
1 分钟和 15 分钟各查询一次，复权基准沿用共享的最新日线；已命中的分钟缓存直接复用。

切分后仍保留五日分时的停牌补线、15:00 截止和 15 分钟跳过停牌日规则。

本次隔离缓存对照覆盖近期、跨半年和停牌日期，行情与旧版一致；
